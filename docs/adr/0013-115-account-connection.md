# 0013 115 账号接入：扫码登录或填写 Cookie，只支持一个账号

- 状态：已接受
- 日期：2026-10-01
- 部分由 ADR 0028 修订：凭据改存 115 插件自己的数据目录，不再存宿主

## 背景

115 的每种设备身份同一时间只允许一个登录会话。同一账号下的其他工具可能已经占用某些身份，再用相同身份登录会把对方踢下线。

## 决策

- 系统只接入**一个** 115 账号，由管理员在管理后台配置。
- 两种接入方式：
  1. **扫码登录**：管理员先选设备身份，再用 115 App 扫码。参考 `javdb115/backend/app/services/p115_login.py` 的实现。
  2. **直接填写 Cookie**：管理员粘贴已有的 Cookie。保存前调用账号信息接口校验是否有效。
- 页面上提示「同一设备身份只能保持一个登录会话，会挤掉其他使用该身份的工具」。由管理员自己选择身份，系统不追踪其他工具的占用情况。
- 凭据加密保存，任何接口和日志都不返回明文。
- 凭据失效（接口返回未登录或被踢下线）时：
  - 暂停同步任务；
  - 播放跳转返回明确的错误；
  - 管理后台醒目提示管理员重新登录。
- 管理后台展示账号信息：用户名、VIP 状态和到期时间、空间用量。

## 备注

- 用户确认：所选设备身份的 Cookie 可以调用导出目录树、列目录和取直链接口。
- 社区经验：用 `web` 身份扫码登录最容易触发「IP 登录异常」类风控，可能要到次日才解除。所以设备身份列表里不默认选 `web`。
- 风控（HTTP 405 拦截页）不等于凭据失效，不触发重新登录，处理方式见 ADR 0007。
- 实现说明（M2）：
  - 凭据用 `APP_SECRET_KEY` 派生的密钥加密（HMAC-SHA256 派生 Fernet 密钥）。更换 `APP_SECRET_KEY` 后旧凭据无法解密，视为未接入，需要重新登录。
  - 校验 Cookie 先调空间接口：凭据失效时它返回 JSON 的「登录超时」（errno 990001），能明确归为凭据失效；`my.115.com` 的用户接口此时返回 HTML 登录页，只能当作暂时性错误。
  - p115client 0.0.9.7.2 的 `login_qrcode` 不会把 uid 发给 115，拿到的是不绑定会话的通用二维码，App 扫了提示「扫描失败」。网关显式传 `params={"uid": uid}`；升级 p115client 时确认不同 uid 拿到的图片不同。
  - 扫码状态接口是长轮询，状态不变时约 30 秒才返回。后端单次等待上限 45 秒，Web 端不能设置「等待响应头」的连接超时，否则轮询会被提前中断。
  - 关闭 HTTP 层自动重试：重试会绕过请求调度器的限速，还会放大风控。
  - 设备身份从 Cookie 的 `UID` 字段推断（形如 `用户ID_R2_时间戳`，`R2` 为支付宝小程序）。
