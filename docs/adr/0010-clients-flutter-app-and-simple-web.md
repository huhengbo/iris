# 0010 客户端形态：Flutter App 负责内置播放，Web 端只调起本机播放器

- 状态：已接受
- 日期：2026-10-01
- 取代：ADR 0004、ADR 0005

## 背景

- 片源以 MKV 为主。浏览器和 iOS 系统自带的播放器都不能完整支持 MKV、DTS/TrueHD 和 PGS/ASS 字幕。
- 用户希望 Web 端尽量简单。倍速、长按加速、滑动调整进度、续播这些体验放在 App 端实现。

## 决策

### 后端
- Python + FastAPI + SQLite，115 访问基于 `p115client`。
- 接口对客户端中立：用 Bearer Token 鉴权，不依赖 Cookie；Web 和 App 共用同一套 API。

### App 端（Flutter，Android 和 iOS）
- 内置播放器基于 mpv 内核（例如 `media_kit`），通过 ADR 0003 的播放跳转**直接播放原画**，不需要转码。
- 内置播放器的功能：
  - 倍速；
  - 长按临时加速，松开后恢复；
  - 水平滑动调整进度；
  - 续播；
  - 切换音轨和字幕。
- 进度上报：播放中定时上报，暂停、切到后台、退出时立即上报。
- 也可以选择本机播放器（Android 用 intent 调起）。

### Web 端
- 只负责浏览（影视墙、详情、搜索、继续观看）、管理后台，以及**调起本机播放器**。不内嵌播放器。
- 调起方式：iOS 用 URL Scheme（Infuse、VLC、nPlayer、SenPlayer 等），Android 用 `intent://` 弹出系统选择器；另外提供「复制播放地址」。
- 走本机播放器时只记录「开始播放」，没有续播进度。用户可以手动标记已看或未看。

### 播放地址鉴权
- 签发给播放器的播放跳转地址带一个短期令牌，绑定用户和文件，不依赖 Cookie。签发前校验可见范围（ADR 0009）。

### 不做
- 115 转码 HLS、自建转码、浏览器内播放器都不进 MVP。

### 代码组织
- Web 端用 **Flutter Web**，与 App 共用一套 Flutter 代码，管理后台也包含在内。播放入口按平台分支：Web 调起本机播放器，App 用内置播放器。
- Flutter Web 的构建产物由后端托管，随服务一起部署（ADR 0002）。
- 已接受的代价：Flutter Web 首次加载较重，手机 Safari 上的滚动和文字手感不如原生网页。

### 分期
- 第一期：后端加 Flutter Web，跑通同步、刮削、影视墙、本机播放器和用户管理。
- 第二期：Android App，加上内置播放器和续播。
- 第三期：iOS App，需要处理签名和分发。
