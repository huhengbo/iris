# 0004 Web 端以浏览器内播放器为主，外部播放器为备选

- 状态：**已废弃**，被 ADR 0010 取代（Web 端不做浏览器内播放器，只调起本机播放器）
- 日期：2026-10-01

## 背景

Web 端需要支持续播、倍速、长按临时加速、左右滑动调整进度。如果交给外部播放器（VLC、Infuse 等），本服务既拿不到播放进度，也控制不了手势，所以这些需求只能由浏览器内的播放器实现。

## 决策

- Web 端默认在页面内播放：使用 HTML5 `<video>` 加自研手势与控制层，视频源仍然走 ADR 0003 的 302 直链跳转（浏览器的 UA 就是取链时用的 UA）。
- 播放器功能：
  - 倍速档位；
  - 长按临时加速，松开后恢复原速；
  - 水平滑动调整进度，并实时预览目标时间点；
  - 断点续播。
- 进度上报：播放中定时上报，暂停、切到后台、关闭页面时立即上报（页面关闭用 `sendBeacon`）。再次打开时从上次位置继续。
- 本机播放器（外部播放器）作为另一种可选的播放方式，由用户选择，见 ADR 0005。走本机播放器时只记录「开始播放」，没有进度。
- 以后的 App 端使用原生播放器，复用同一套进度接口和手势设计。

## 影响与约束

- **iPhone Safari 的全屏**：iPhone 上不支持对普通元素使用 Fullscreen API，系统全屏会切到原生控件，自定义手势会失效。所以手机端的「全屏」用页面内横屏铺满（伪全屏）实现；添加到主屏幕（PWA）后可以去掉浏览器地址栏。
- 浏览器的解码能力取决于平台，容器、视频编码、音频编码和字幕都可能不支持（例如 MKV、DTS/TrueHD、PGS 字幕）。不支持时如何回退见后续 ADR。
- 302 跳转后浏览器请求 115 CDN 会带上 `Referer`，需要实测是否被拒；必要时把页面的 referrer 策略设为 `no-referrer`。
