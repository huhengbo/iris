# 0003 播放采用 302 直链跳转，视频流不经过服务端

- 状态：已接受（用户根据实际使用确认：直链不绑定来源 IP）
- 日期：2026-10-01

## 背景

- 115 直链有时效，并且绑定取链时的 User-Agent：直链参数 `f=1` 时要求 UA 一致，`f=3` 时还需要带取链响应中的 Cookie。
- 获取直链需要 115 登录凭据，凭据不能下发给客户端，所以「取链」这一步只能放在服务端。
- `javdb115` 采用的是服务端代理拉流，可靠但会占用服务器带宽。用户希望尽量不走代理。

## 决策

- 客户端（外部播放器或以后的 App 内置播放器）访问本服务的播放跳转地址。服务端用**该请求的 User-Agent** 获取直链，然后 302 跳转，视频字节由播放器直接从 115 CDN 拉取。
- 直链缓存按 `(pickcode, User-Agent)` 区分，缓存时长短于直链本身的有效期。
- 选择能返回 `f=1`（只绑定 UA）直链的取链接口。参考实现见 Mi302、115-Station、p115dav：它们走的是 android 端下载接口。
- 播放跳转地址用不依赖 Cookie 的短期令牌鉴权，因为外部播放器无法携带登录态。
- M6 已实现，跳转支持 `GET` 和 `HEAD`。播放器只认状态码，所以失败时只返回状态码和简短说明：令牌无效 401、过期 410、文件失效 404、同一令牌请求过频 429（带 `Retry-After`，ADR 0015）、风控或凭据问题 503（风控时带 `Retry-After`）、115 连不上 502。

## 风险与回退

- 用户确认直链不绑定来源 IP，所以服务端和播放器不在同一网络时也能使用 302。
- 2026-10-02 在真实部署上实测：
  - 服务器取到的 `f=1` 直链换到手机 IP 后，只要 UA 一致就能下载；换 UA 返回 403 invalid signature；
  - 同一直链最多 3 个并发连接，第 4 个返回 403；
  - App 内置播放器（UA `libmpv`）302 后能正常播放，拖动时会再次请求跳转地址。
- 如果个别播放器在 302 之后不保留 UA，再考虑为该播放器回退到服务端代理拉流（参考 `javdb115/backend/app/api/playback_stream.py`）。MVP 不实现代理。
