# 0017 客户端与服务端相互独立，客户端可以配置和切换服务器

- 状态：已接受
- 日期：2026-10-01
- 补充：ADR 0002、ADR 0010

## 背景

- 以后会有 Android（包括电视）客户端，它要像 Emby 客户端那样，由用户填写服务器地址，可以保存多个服务器并切换。
- 同一台服务器可能有多个地址（局域网地址、公网域名），客户端要认得出是同一台。
- ADR 0002 让 Web 构建产物由后端托管，这只是部署上的方便，不能让前后端在代码上互相依赖。

## 决策

### 服务端：接口是唯一契约
- 所有后端资源都在 `/api` 下（播放跳转 `/play` 除外，它发给外部播放器，见 ADR 0015）。前端托管只是兜底路由，后端不做页面渲染，不依赖 Cookie 和同源。
- **服务器自我描述**：`GET /api/system/info`，不需要登录。返回 `product`（固定为 `iris`）、`server_id`（首次启动时生成，之后不变）、`server_name`（管理员可改）、`version` 和 `api_version`。客户端添加服务器时先调用它，确认地址指向的是本服务。
- **地址都是相对的**：响应中的图片等地址都是相对服务器根的路径（例如 `/api/images/…`），客户端按自己连接的服务器地址拼接。服务端不根据请求的 Host 生成绝对地址。发给外部播放器的播放地址是例外，按管理员配置的对外访问地址生成（ADR 0015）。
- **图片**：`[{width, url}]`，宽度从小到大，客户端按显示尺寸挑选。图片不需要登录（`<img>` 不能带令牌，内容都来自 TMDB 的公开图片，文件名含内容哈希，无法枚举），可以永久缓存。
- **跨域**：默认不开。单独部署 Web 客户端时，通过 `APP_CORS_ORIGINS` 列出允许的来源。只用 Bearer 令牌，不需要跨域携带 Cookie。App 不受跨域限制。

### 接口规范
- 路径用复数名词表示资源（`/api/admin/libraries/{id}`），对资源的动作用 `POST /…/{id}/动作`（例如 `/refresh`）。普通用户接口和管理接口（`/api/admin/…`）分开。
- 字段用 snake_case；时间用带时区的 ISO 8601；ID 是整数。
- 错误统一为 `{"error": {"code", "message", "details"?}}`。`code` 是稳定的英文标识，供客户端判断；`message` 是可以直接展示的中文。
- 数量有上限的列表直接返回数组。可能很长的列表返回 `{"items", "total"}`，用 `offset`、`limit` 分页。
- **兼容**：只增加字段、接口或枚举值时不改 `api_version`，客户端必须忽略不认识的字段，并能处理不认识的枚举值。删除、改名或改变语义时把 `api_version` 加一，客户端发现自己不支持时提示升级。

### 客户端
- 保存服务器列表：地址、`server_id`、名称。令牌按 `server_id` 分开保存，切换服务器时只换地址和令牌，并清空所有缓存的页面数据。
- 接口调用集中在各功能的数据访问类里（现有的 `*_api.dart`），页面不直接拼接口路径，也不拼图片地址。
- Web 端由后端托管时，默认服务器就是页面所在的地址，用户不需要配置。
- 服务器管理界面（添加、切换、删除服务器）已随提前做的 Android App 实现（`lib/core/servers.dart`、`lib/features/servers/`）；Web 端连页面所在的服务器，不需要管理。

## 不做
- 客户端连接 Emby 或 Jellyfin 服务器。需要时另行决策。
- 局域网自动发现服务器。
