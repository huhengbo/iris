# 0016 按作品识别和匹配，手动结果锁定，图片按用途分档

- 状态：已接受
- 日期：2026-10-01
- 补充：ADR 0008、ADR 0012

## 背景

- 资料库多数已按 MoviePilot 的习惯整理：「片名 (年份)/片名 (年份) - 2160p.mkv」「剧名 (年份)/Season 1/剧名 - S01E01.mkv」。同一目录下的视频属于同一部作品，按文件逐个搜索 TMDB 既浪费请求，又可能把同一部剧的不同集匹配到不同条目。
- 部分目录带有 NFO，里面有可靠的 TMDB ID 或 IMDb ID，比按片名搜索准确。
- 管理员手动修正的结果必须稳定，不能被下一次同步改回去。

## 决策

### 作品
- 识别时把视频按**作品目录**分组为「作品」（`work`）：电影目录或剧集目录，季目录（`Season 1`、`S01`、`Specials`、`第一季`）归入上一级。整组一起匹配 TMDB，同一作品下的文件挂到同一个条目。
- 作品的片名、年份从目录名解析；资料库目录本身就是作品目录时，用资料库目录的名字。
- 作品的状态：`pending` 等待匹配（新识别，或上次未配置 TMDB、请求失败），`matched` 已匹配，`unmatched` 没找到或不能确定（记录原因和最多 8 个候选）。

### 匹配顺序
1. 路径里的 `{tmdb-123}` 标记；
2. 作品 NFO 里的 TMDB ID；
3. 作品 NFO 里的 IMDb ID（通过 TMDB 的 find 接口换成 TMDB ID）；
4. 按片名搜索（目录名解析出的片名、另一种语言的片名、去掉括号内容的片名，依次搜索），从每次的结果中挑出可以确定的一个：
   - 有年份时，同年的唯一结果直接采用；没有同年的放宽到前后一年；仍有多个时，取片名或原名与目录名一致的结果中相关度最高的；
   - 没有年份时，只接受片名一致的唯一结果。
- 前一步的 ID 在 TMDB 上不存在时继续下一步。都不成功时进入待处理。

### NFO 只读 ID
- 剧集读取作品目录下的 `tvshow.nfo`；电影优先 `movie.nfo`，其次与视频同名的 NFO，目录下只有一个 NFO 时就用它。上限 256KB；只取 `uniqueid`、`tmdbid`、`imdbid` 和 TMDB、IMDb 链接，用正则提取（各工具写法不规范，也避免 XML 解析的实体展开风险）。剧集资料库里指向电影的 TMDB 链接不采用。
- NFO 的 `sha1` 没变就不再下载；只在作品还在等待匹配时读取，已匹配的作品不再请求 115。
- 标题、简介、图片仍以 TMDB 为准，不读取 NFO 中的其他字段，也不读取 115 中的图片。

### 手动结果锁定
- 管理员在待处理里指定作品或单个文件、改挂版本后，作品或版本标记为 `manual`，同步的自动匹配和归位都跳过它们。
- 管理员把版本「拆出」后，文件标记为 `detached`，进入待处理的「未归入」列表，同步不会自动放回原处。
- 「重新匹配」清除作品的匹配结果（包括手动指定）和读过的 NFO，重新走匹配顺序；也可以直接指定另一个 TMDB 条目。

### 附加内容
- 在 ADR 0012 的规则上补充：蓝光原盘目录（`BDMV/STREAM`）里每张盘只保留最大的一个文件，其余视为原盘中的非正片片段。
- 被忽略的文件记录原因，显示在待处理的「已忽略」列表里，管理员可以手动指定恢复。体积阈值修改后在下次同步时生效。

### 刮削范围与刷新
- 条目首次匹配时拉取详情和演职员：演员取前 20 位，剧集用 `aggregate_credits` 汇总各季演员；导演（电影）和主创（剧集）去重保存，供演员页使用（M5 已实现）。
- 剧集只建有文件的季和集。季的 `scraped_at` 为空表示需要拉取：新建的季、有新集入库的季、上次未配置 TMDB 或请求失败的季。同步只拉取这些季，不刷新其他季和条目详情。
- 语言为 `zh-CN`，标题和简介为空时回退到 `en-US`。海报和背景图用 TMDB 按 `zh-CN` 给出的默认图；横版图和片名图带文字，只从中文和英文的图里按评分挑选，中文优先。
- 管理员可以对单个条目「刷新信息」（详情、演职员、全部季），或「重新读取文件」（到 115 重新列出条目文件所在的目录，更新大小、`sha1` 和失效状态）。同步运行期间不能重新读取文件。

### 同步阶段
准备（`preparing`）→ 导出（`exporting`；定向同步不导出，改为列目录 `listing`）→ 补全（`enriching`）→ 识别（`recognizing`，含读取 NFO）→ 匹配（`matching`，含挂版本）→ 拉取季信息（`scraping`）→ 下载图片（`images`）。统计里增加匹配、未匹配、忽略和等待匹配的数量。
- 没有配置 TMDB 时，作品停在等待匹配，同步不算失败，任务里记录提示；TMDB 的 Key 失效或无法连接时中止本阶段，剩下的下次同步继续。
- NFO 读取失败只影响该作品改用片名搜索。

### 图片
- 类型参考 Emby：`poster` 竖版海报、`backdrop` 背景图、`thumb` 带片名的横版图、`logo` 透明片名图，以及季海报、集剧照 `still`、人物头像 `profile`。
- 从 TMDB 下载一个尺寸，本地再缩放出其他档位：

  | 类型 | 下载 | 本地档位 | 用途 |
  | --- | --- | --- | --- |
  | poster | w780 | 780、342 | 详情页、海报墙 |
  | backdrop | w1280 | 1280、780 | 宽屏、手机 |
  | thumb | w780 | 780 | 首页横向列表 |
  | logo | w500 | 500（PNG，保留透明） | 叠在详情页背景图上 |
  | still | w300 | 300 | 集列表 |
  | profile | w185 | 185 | 演职员 |

- 文件按内容哈希命名（128 位），内容相同的图片共用文件；访问路径 `/api/images/{hash}_{width}.{ext}`，不需要登录，可以永久缓存（ADR 0017）。
- 同步结束和管理员操作后清理不再被引用的图片；共用文件的图片只在没有任何引用时删除。

## 影响

- 一个目录里放了多部不相关的电影时，会被当成一部作品；这类目录需要管理员拆出版本后逐个指定。
- 只按需拉取季信息，TMDB 上已有条目的后续修改（新海报、简介更新）要管理员手动刷新才会同步过来。
