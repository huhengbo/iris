# 0008 元数据只来自 TMDB 并独立存储，图片缓存在本地

- 状态：已接受
- 日期：2026-10-01
- 修订：2026-10-01，NFO 中的 TMDB ID 和 IMDb ID 用于匹配，图片类型参考 Emby（见 ADR 0016）

## 背景

- 115 目录名里没有 tmdbid。
- 部分目录有 MoviePilot 生成的 NFO 和图片，但不完整；逐个读取还会大量请求 115，容易触发风控。

## 决策

- 元数据完全由本系统独立维护：**不读取** 115 中的图片，NFO 只读取其中的 TMDB ID 和 IMDb ID 用于匹配，标题、简介等其他字段不采用（ADR 0016）。
- 刮削源只用 TMDB：
  - 语言用 `zh-CN`，没有中文时回退到英文；
  - 识别时先用路径里的 `{tmdb-ID}` 标记和 NFO 里的 ID，没有时按目录名和文件名解析出的片名、年份搜索，置信度不足的进入「待处理」。
  - TMDB 的 API Key 和 HTTP 代理都可以在管理后台配置。
- **持久化**：TMDB 返回的条目信息（电影，以及剧集、季、集）写入数据库，浏览时不请求 TMDB。
- **图片缓存**：海报、背景图、横版图（thumb）、片名图（logo）、剧照、头像在刮削时下载到服务端本地存储，并生成影视墙要用的几档尺寸（ADR 0016）。前端只从本服务加载图片。
- **何时刷新**：
  - 条目首次匹配时拉取一次；
  - 剧集有新的集文件入库时，刷新对应的季信息；
  - 管理员可以对单个条目手动「刷新信息」或「重新匹配」；管理员手动指定的匹配结果，同步不会改动。
  - 不做定期的全量刷新。
- 刮削请求限速，避免触发 TMDB 的频率限制。

## 影响

- 本地存储的占用会随资料库规模增长，需要在部署时挂载持久化卷。
- 豆瓣等其他刮削源不进 MVP。
