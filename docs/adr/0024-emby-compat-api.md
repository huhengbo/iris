# 0024 提供 Emby 兼容接口，第三方客户端用长期设备令牌直连播放

- 状态：已接受
- 日期：2026-10-23
- 补充：ADR 0003、ADR 0009、ADR 0015、ADR 0017

## 背景

用户希望 Infuse、网易爆米花这类支持 Emby 协议的第三方客户端，能把本服务当成 Emby 服务器直接连接、浏览和播放，而不只是由 Iris 调起后播一个链接。这些客户端的约定和本服务现有的设计有几处冲突：

- 它们用用户名和密码登录，拿到的令牌默认长期有效；本服务的访问令牌只有 15 分钟，靠刷新令牌续期。
- 它们会自己拼 `/Videos/{id}/stream?api_key=…` 交给播放器，不使用服务端给出的 24 小时播放令牌地址。
- 有的客户端请求 `/emby/…`，有的直接请求根路径 `/Items/…`；现在根路径由 Web 客户端的兜底路由占用。

## 决策

- **在核心里实现，不做成插件**：插件 SDK 只能处理 `/api/plugins/{id}/…` 下的请求，不能注册根路由，也不能接触用户令牌（ADR 0021）。
- **和 Web 同一个端口**：同时支持 `/emby/…` 和根路径。根路径下只接管 Emby 的大写前缀（`Users`、`Items`、`Videos`、`System` 等），这些路由注册在前端兜底路由之前，其余路径仍交给 Web 客户端。
- **始终开启**：只开放浏览、播放、播放进度、已看和收藏，不开放管理功能。管理员通过这套接口登录也没有管理能力。可见范围沿用 ADR 0009。`/Users/Public` 始终返回空列表，不公开用户名。
- **只做直接播放**：沿用 ADR 0003，302 跳转到 115 直链，不转码，也不代理拉流；PlaybackInfo 只声明 DirectPlay。依赖转码的客户端和格式不在支持范围内。
- **客户端设备令牌**：用本服务的账号密码登录，每次登录记为一个客户端设备，令牌长期有效。用户被禁用、修改密码或可见范围变化（`token_version` 递增）时失效。用户可以撤销自己的设备，管理员可以撤销任何用户的设备。
- **串流地址接受设备令牌**：这是 ADR 0015「播放跳转只认 24 小时播放令牌」的例外。限流和播放令牌相同，按设备计数：每分钟 120 次跳转，每小时 30 次取链。
- **图片和字幕允许不带令牌**：客户端拉图片和字幕时常常不带令牌。图片入口完全不鉴权，最终跳转到的 `/api/images` 本来就是公开的。字幕要从 115 取链，所以只放行某台设备最近 12 小时请求过播放的版本，并沿用这台设备的身份和限流；设备被撤销后立即失效。

## 考虑过的方案

- **单独端口**：完全不会和 Web 路由冲突，但部署时要多配一套反向代理和地址。
- **在 PlaybackInfo 里给出播放令牌地址**：不少客户端会忽略这个地址，自己拼 `/Videos` 地址，兼容性差。
- **用应用密码代替账号密码登录**：客户端的登录界面只有用户名和密码，用起来别扭。

## 影响

- 设备令牌会出现在串流地址里，可能被反向代理写进访问日志。令牌泄露后只能靠撤销设备补救，部署文档要提醒这一点。
- 第三方客户端隔了 24 小时以上再从自己的历史记录重播，仍然可以播放。
- 第三方客户端上报的进度和内置播放器一样写进播放进度，播到 90% 时自动标记已看。
- 为了兼容 Emby，新增「收藏」功能，Iris 自己的客户端也一起支持。
- 验收以 Infuse 和网易爆米花实测通过为准，不承诺 Emby 官方 App 和 Jellyfin 客户端。
