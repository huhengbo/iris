# 0029 插件仓库：可配置多个，管理员浏览、安装、升级、卸载；系统插件不变

- 状态：已接受
- 日期：2026-10-31
- 修订：ADR 0028（“第三方插件安装、升级不在这次范围”改为本 ADR；“从宿主插件目录发现的插件统一记录为内置”改为只有系统插件是内置）

## 背景

ADR 0028 把全部插件移到进程外，插件是独立包、独立 venv，目录结构可以原样搬到单独仓库，宿主已经能按 manifest 加载第三方包，但没有安装、升级界面。用户之后会在一个新的官方插件仓库里加入大量自定义插件，宿主需要默认配置这个仓库，并允许再配置其他仓库。现有 6 个插件（`builtin.*`）保持随镜像发布，不变。

## 决策

### 仓库与插件来源

- **插件仓库**由一个地址标识，发布 `index.json`（带 schema 版本）和各插件的压缩包。可以配置多个。
- **官方仓库**是宿主默认配置的仓库，地址写在宿主默认配置里，环境变量 `APP_DEFAULT_PLUGIN_REPOS` 可覆盖（内网镜像）。界面上可以停用，不能删除；用户添加的仓库可以停用也可以删除。
- **系统插件**即现有 6 个 `builtin.*`：随镜像升级，不能被仓库覆盖、升级或卸载，只能停用；`builtin.` 前缀保留，仓库插件不得使用。仓库里出现同 id 的插件视为冲突，忽略并提示。
- 插件有三种来源：系统、某个仓库、本地。

### 仓库形态

- 官方仓库是 git 源码仓库（建议 `huhengbo/iris-plugins`，公开），CI 生成静态 `index.json` 和每个插件的压缩包，索引托管在 Pages，压缩包放 Release。宿主只认索引和压缩包，不依赖 git。
- 索引每个条目包含 id、名称、版本、描述、SDK 兼容范围、`provides`、`capabilities`、下载地址和 sha256，并预留可选 `signature` 字段（这次不做签名校验）。
- 仓库地址和下载地址一律 HTTPS（本机开发可用 localhost）。宿主拉取索引和压缩包使用宿主已有的有效代理。宿主不认识的 schema 版本显示为不支持；SDK 范围不匹配的插件显示为不兼容、不可安装。
- 新仓库这次只做脚手架：目录规范、CI 出索引、一个仅用于端到端验证的示例插件；不做正式发布。

### SDK

- `iris-plugin-sdk` 发布到 PyPI，仓库里的插件按普通依赖声明它，包自包含。不使用 git 依赖：运行时镜像没有 git，`huhengbo/iris` 也是私有仓库，宿主装不了。因此仓库插件的真实安装要等 SDK 先发布到 PyPI，实现在 SDK 发布之后开始。

### 安装

- **依赖**：运行时镜像加入 `uv`；安装时解压压缩包，先 `uv export --frozen --no-dev --no-emit-project` 导出带哈希的依赖清单，再 `uv pip install --require-hashes` 装进插件自己的 venv，最后 `uv pip install --no-deps` 装插件本身。版本和哈希仍由插件自带的 `uv.lock` 锁定。不用 `uv sync --frozen`：它直接使用 `uv.lock` 里记录的下载地址，不认 `UV_DEFAULT_INDEX` 等镜像配置（uv 维护者确认为有意设计，astral-sh/uv#19625），内网或国内无法换源。PyPI 镜像用 `UV_DEFAULT_INDEX` 等环境变量配置。安装时需要能访问 PyPI 或其镜像。
- **存放**：代码和 venv 放在 `data/plugin-packages/<id>/<版本>/`；插件状态仍在 `data/plugins/<id>/state/`（ADR 0028）。备份只包含各插件状态和「已安装清单」（id、版本、来源仓库），不包含代码和 venv；恢复后宿主按清单重新安装缺失的插件。
- **生效**：安装、升级、卸载后热加载，不重启宿主。升级时停掉旧进程、切换版本目录再拉起，保留上一个版本目录；新版本拉起失败自动回滚。
- **本地安装**：管理员在管理端上传压缩包，走同样的校验、确认和热加载流程，依赖仍联网安装。来源记为「本地」，不参与更新检查，升级靠再上传更高版本；该 id 已由某仓库安装时拒绝上传，需先卸载。

### 信任

- 仓库安装校验索引里的 sha256。添加非官方仓库时弹出风险确认；安装前展示插件声明的 `provides` 和 `capabilities`，由管理员确认。本地安装没有索引 sha256，每次上传都做同样的风险确认。
- 不做签名校验，不做沙箱。插件仍是管理员信任的代码，可以直连外网、读写自己的 state（ADR 0028）。

### id 与升级

- 已安装的插件 id 全局唯一。安装时记录来源仓库，升级只看该仓库；另一个仓库里的同 id 插件显示为冲突，不可安装。
- 新增计划任务每天拉取各仓库索引并缓存，插件页显示“有更新”；升级由管理员手动触发。拉取失败时保留上次缓存，并显示仓库错误状态。

### 卸载

- 有资源来源在用的插件拒绝卸载，要求先删除来源；元数据、图片、字幕插件从各资料库的下载器列表中自动移除。
- 卸载默认保留插件 state（密钥、配置），对话框里可勾选「同时删除数据」。

### 界面

- 插件页增加「目录」（浏览仓库、安装、升级）和「本地安装」入口，沿用 Emby 的插件目录交互（ADR 0025）。TV 端不做。

## 取舍

- 运行时镜像多一个 `uv`，安装依赖需要联网访问 PyPI 或镜像；完全无网络环境不能安装，本地安装也一样。
- 备份不含插件代码：包小、不受平台影响，代价是恢复时依赖仓库在线和 PyPI 可访问；任一不可用时对应插件需要手动重装。
- 不做签名：第一版不管理密钥和轮换，信任等同于托管账号和 HTTPS，加上 sha256 只能发现传输中的篡改，不能防止仓库本身被污染。
- 热加载比重启复杂，但不会中断正在播放的用户。
- 不强制官方前缀：id 抢注靠“已装全局唯一”和来源提示处理，不做命名空间所有权校验。

## 结果

- 默认就有官方仓库可浏览；管理员可以添加多个仓库，也可以上传压缩包安装。
- 系统插件行为不变，不会被仓库覆盖。
- 之后往官方仓库加插件目录即可，CI 出索引和包，宿主不需要改。
