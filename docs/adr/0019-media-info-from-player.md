# 0019 流信息由内置播放器上报

- 状态：已接受（真机待验证）
- 日期：2026-10-03
- 补充：ADR 0012

## 背景

- 详情页只能显示文件名里解析出的标签（「2160p · WEB-DL · DV」），看不到实际的编码、HDR、音轨和内封字幕。选版本时最想知道的「有没有国语音轨」「有没有中文内封字幕」也答不上来。
- Emby 的做法是服务端用 ffprobe 探测每个文件。放在本系统里有几个问题：
  - 文件在 115 上，探测一次要取直链并读文件头（大文件的 moov 可能在末尾），扫描几千个文件就是几千次额外请求，容易触发风控；
  - 服务端要多装 ffmpeg；
  - 探测要么拖慢扫描，要么另起一个后台队列。
- 内置播放器（mpv）每次播放都会自己读一遍容器头，这些信息本来就有，只是用完就丢了。

## 决策

- 服务端不探测文件。内置播放器打开文件、读到时长和画面参数之后，把 mpv 的 `track-list` 和 `video-params` 整理好，上报 `PUT /api/versions/{id}/media-info`，每次播放报一次。
  - 外挂字幕是本系统挂上去的，不算在内封字幕里；封面图（`image`）不算视频轨。
  - HDR：视频轨带 `dolby-vision-profile` 时是杜比视界，否则按 `video-params` 的 gamma 判断（`pq` 为 HDR10，`hlg` 为 HLG）。
  - 上报失败不提示、不重试，不影响观看，下次播放再报。
- 流信息按云端文件存（`media_info` 表），所有能看到这个版本的用户共用，后报的覆盖先报的。
  - 存下上报时文件的大小和 sha1，文件被替换后对不上就不再使用，等下一次播放重新上报。
- 详情页的版本带上 `media`：画面（分辨率档位、编码、HDR）、音轨（语言、编码、声道）、内封字幕（语言、格式、强制）。没人用内置播放器播过的版本为 `null`，界面上不显示这一块。
- 上报内容来自片源，服务端校验长度和条数（语言 16 字、标题 200 字、编码 32 字，音轨 64 条、字幕 128 条），客户端超长的字段先丢掉再报。

## 后果

- 不增加任何 115 请求，也不增加起播时间。
- 只用外部播放器（iOS、Web）的用户看不到流信息，直到有人用 App 的内置播放器播过一次。
- 流信息只是给人看的，不参与选版本或选字幕。按音轨、内封字幕语言预选要等这份数据足够可靠之后再做。
- 能读到哪些字段取决于 App 打包的 mpv 版本，例如较旧的 mpv 没有 `dolby-vision-profile`，杜比视界会显示成 HDR10。

## 不做

- 服务端 ffprobe、扫描时探测。
- 在详情页提供「立即分析」。
