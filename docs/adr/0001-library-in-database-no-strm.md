# 0001 影视数据以数据库为准，不生成 STRM

- 状态：已接受
- 日期：2026-10-01

## 背景

MoviePilot 和 Emby 的组合需要生成 STRM，是因为 Emby 只能扫描本地文件系统。本应用自己提供影视墙和播放入口，不需要第三方媒体服务器来读取这个库。

## 决策

- 扫描、识别、刮削的结果直接写入本应用数据库，影视墙和播放只依赖数据库。
- 云端文件只保存 `pickcode`/`file_id` 引用；播放时按需获取直链。
- 刮削得到的元数据持久化保存，浏览时不重新请求刮削源。
- 不生成 STRM。以后如果需要让 Emby/Jellyfin 共用这个库，再把 STRM 作为可选导出功能单独设计。
- 只参考 MoviePilot 的识别和刮削逻辑，不依赖 MoviePilot 运行。

## 影响

- 省掉一层文件和数据库之间的同步，也不会出现文件已删除但 STRM 还在的不一致。
- 115 中的文件被移动或删除后，要靠重新同步来发现失效引用。
